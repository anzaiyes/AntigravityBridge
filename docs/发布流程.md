# 发布流程

## 未公证发布

没有 Developer ID 时，使用以下命令生成明确标记为未公证的发布包：

```bash
./tests/run-tests.sh
./scripts/package.sh v2.2.0
```

产物包括：

- `dist/Antigravity-Bridge-v2.2.0-unsigned.zip`
- `dist/SHA256SUMS`

`package.sh` 会重建 App、进行 ad-hoc 签名、验证签名、创建不含 Finder 元数据的 ZIP，并计算 SHA-256。

推送与 `Info.plist` 版本相同的 `v*` 标签后，GitHub Actions 会运行相同检查并创建 Release。Release 必须明确说明该 App 尚未经过 Apple Developer ID 签名或 Apple 公证。

## Developer ID 与 Apple 公证

取得 Apple Developer Program 资格及 Developer ID Application 证书后，可以使用：

```bash
xcrun notarytool store-credentials "antigravity-bridge-notary"
SIGN_IDENTITY="Developer ID Application: ..." \
NOTARY_PROFILE="antigravity-bridge-notary" \
./scripts/sign-and-notarize.sh
```

脚本将执行：

1. 从干净源码重建 App。
2. 使用 Developer ID、Hardened Runtime 和安全时间戳签名。
3. 提交临时 ZIP 到 Apple notary service 并等待结果。
4. 将公证票据 staple 到 App 并验证。
5. 重新生成最终 ZIP 和 SHA-256。

不要把证书文件、Apple ID、App 专用密码、notarytool 凭据或导出的钥匙串提交到仓库。为 GitHub Actions 增加正式签名时，应使用受保护的 GitHub Secrets 和最小权限环境，并确保 Fork PR 无法读取这些 Secrets。

## 发布检查清单

- `Info.plist` 版本与标签一致。
- `./tests/run-tests.sh` 全部通过。
- ZIP 不含 `.DS_Store`、`._*` 或 `__MACOSX`。
- `SHA256SUMS` 可以验证。
- Release Notes 明确签名和公证状态。
- 在开启 Gatekeeper 的干净 macOS 用户环境中完成首次启动测试。
- 更新 `CHANGELOG.md`。
