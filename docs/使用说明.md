# Antigravity Bridge v2.2 使用说明

## 支持范围

- Clash Verge / Clash Verge Rev
- ClashX / ClashX Meta
- Mihomo Party 及兼容 Clash YAML 配置的客户端
- Surge for Mac
- macOS 当前启用的 HTTP、HTTPS 或 SOCKS 系统代理
- 任意在本机监听的 HTTP/Mixed 或 SOCKS5 代理

## 首次运行

1. 保持代理客户端核心运行，TUN 可以关闭。
2. 如果 Antigravity 已打开，用 `Command-Q` 完全退出。
3. 双击 `Antigravity Bridge.app`。
4. 启动器会寻找 Antigravity，并验证检测到的代理端口。
5. 从弹出的列表选择一个代理；也可以选择“手动配置…”，输入类型和端口。

列表会将评分最高的候选项移到首位、标记为 `★ 推荐` 并默认选中。推荐优先考虑：能够访问 Antigravity 专用端点、HTTP/Mixed 兼容性、本机回环监听，以及可信的系统或客户端配置来源。

配置保存在当前用户的：

`~/Library/Application Support/Antigravity Bridge/config.plist`

从旧版升级时，会自动复制并继续使用 `Antigravity Proxy` 保存的配置，不需要重新选择代理。

不同 macOS 用户拥有各自独立的配置。配置的代理失效或端口发生变化时，启动器会自动重新探测并再次询问。

## 日常使用

把 `Antigravity Bridge.app` 拖入 `/Applications` 或固定到 Dock。以后从这个图标启动 Antigravity。启动器完成启动后会自动退出，不需要保持任何窗口打开。

## 自动发现逻辑

- 在 `/Applications`、`~/Applications` 和 Spotlight 中按 Bundle ID 查找 Antigravity。
- 读取 macOS 系统代理。
- 读取 Clash/Mihomo 的常见活动配置文件。
- 读取 Surge Profile 的 `http-listen` 和 `socks5-listen`。
- 探测 Clash 和 Surge 常用端口。
- 候选端口必须通过对应 HTTP 或 SOCKS 协议连接验证，才会显示在列表中。

## 行为边界

- 只代理 Antigravity 进程树。
- 不打开 TUN。
- 不修改系统代理、路由或代理客户端配置。
- 不修改 Antigravity 应用。
- 不读取、保存或转发 Google 登录凭据。

## 重新配置和诊断

如果已保存的代理无法使用，下一次启动会自动重新配置。

也可以在终端主动重新配置：

```bash
"/Applications/Antigravity Bridge.app/Contents/MacOS/antigravity-bridge" --configure
```

查看自动发现结果：

```bash
"/Applications/Antigravity Bridge.app/Contents/MacOS/antigravity-bridge" --diagnose
```
