# Antigravity Proxy Launcher v2 Design

## Goal

Provide a portable native macOS application launcher that starts Antigravity with a process-scoped local proxy, without requiring TUN mode, changing global proxy settings, or keeping a terminal window open. Support Clash Verge, ClashX, Surge and compatible HTTP/SOCKS listeners.

## Architecture

The deliverable is a minimal macOS App Bundle. Its executable is a Bash script launched by Finder or Dock. Discovery reads the active macOS system proxy, known Clash/Mihomo YAML files, and Surge profiles, then probes common listener ports. Every candidate is validated with its declared HTTP or SOCKS protocol before it is shown. Mixed listeners are used as HTTP proxies.

Candidates receive an explainable recommendation score. Successful access to the Antigravity service endpoint has the highest weight, followed by HTTP/Mixed compatibility, loopback-only binding, and a known system/client source. The highest-scoring option is moved to the top, prefixed with `★ 推荐`, selected by default, and accompanied by a plain-language reason in the selection prompt.

On first run the user chooses a validated candidate or enters a type and port manually. The selection and discovered Antigravity path are saved in the current user's `~/Library/Application Support/Antigravity Bridge/config.plist`. Existing `Antigravity Proxy` configuration is copied during migration. Subsequent launches reuse the configuration while it remains valid, and return to discovery when it does not.

Antigravity discovery first verifies common `/Applications` and `~/Applications` locations, then queries Spotlight for bundle identifier `com.google.antigravity-ide`, with a native application picker as fallback. Launching uses macOS `open --env` to inject proxy variables into the new Antigravity process tree. Chromium proxy flags cover Electron traffic, while `NO_PROXY` and the Chromium bypass list preserve Antigravity's localhost bridge.

The launcher exits immediately after a successful launch. Antigravity and `language_server` retain their inherited environment independently.

## Error Handling

- Missing Antigravity: show a native alert and exit.
- No detected proxy: offer manual HTTP/Mixed or SOCKS5 configuration.
- Invalid or unavailable selected proxy: do not save it; show a native alert and retry on the next launch.
- Stale saved proxy: rerun discovery and selection automatically.
- Antigravity already running: do not quit it automatically; explain that the current process cannot be retrofitted with environment variables.
- Launch failure: show the returned status in a native alert.

## Acceptance Tests

1. `Info.plist` passes `plutil -lint`.
2. Executable passes `bash -n`.
3. Diagnostic mode discovers the locally running proxy with the correct protocol and port.
4. Configuration round-trip tests pass in an isolated temporary user directory.
5. Bundle reports the expected identifier, executable, and icon.
6. App is ad-hoc code signed for unnotarized builds and passes `codesign --verify`.
7. Launcher contains no command that changes proxy clients, system proxy, routes, or the original Antigravity bundle.
8. HTTP and SOCKS launch URLs are constructed correctly and localhost is bypassed.
9. Release ZIP contains no `.DS_Store`, AppleDouble, or `__MACOSX` entries and its SHA-256 verifies.
